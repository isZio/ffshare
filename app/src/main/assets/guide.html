场景配方 输出与命名 压缩强度 编码器 分辨率与体积 保存与缓存 其他 常见问题

场景配方

发微信群 / QQ 怕超限

  • 视频编解码器：H.264（硬件加速，更快）
  • 最大视频分辨率：1080（更小的选 720）
  • 视频文件大小上限：25M（群文件）/ 10M（聊天直发）
  • 音频编解码器：直接复制

发朋友圈 / 抖音 画质优先

  • 视频编解码器：不指定（软件 libx264）
  • 视频 CRF：23；压缩预设：medium
  • 最大视频分辨率：1080；体积上限：不限制

存档 / 二次剪辑素材 尽量无损

  • 视频 CRF：18 ~ 20；预设：slow（慢但省体积）
  • 最大视频分辨率：不限制
  • 保留 Exif 标签：开（留住拍摄时间/机型）
  • 输出文件名：原始文件名，便于回溯

手机 4K 录像要发出去 又快又小

  • 视频编解码器：H.264（硬件加速）
  • 最大视频分辨率：1080（4K 压 1080p，体积能降 70% 以上）
  • 视频文件大小上限：8M 或直接不限制

录屏教程 / 满屏文字 别用硬件

  • 视频编解码器：不指定（软件 libx264）——硬件编码会把文字边缘糊成毛边
  • 视频 CRF：26（文字场景观感依然够）
  • 压缩预设：fast 节省时间

老手机 / 怕发烫 / 批量处理 省电

  • 视频编解码器：H.264（硬件加速）
  • 最大视频分辨率：720
  • 压缩预设：fast；CRF 26

图片批量转发 只压图片

  • JPEG 图片质量 qscale：10（清晰）/ 18（省空间）
  • 最大图像分辨率：2160（长边像素，超过就缩）
  • 保留 Exif 标签：建议关（抹掉定位信息）

语音 / 音乐转码 兼容优先

  • 音频编解码器：AAC（跨平台最稳），输出扩展名选 .m4a 或保持原格式
  • 只想换容器不重编码：编解码器选 Copy，几秒完成，体积不变

输出与命名

输出媒体文件名称 默认：随机编号(UUID)

是什么：压缩结果的文件名规则。
三个选项：原始文件名 / 随机编号 / 自定义。选「自定义」后会多出一行输入框（自定义输出媒体名称），只填文件名、不要带扩展名。
什么时候改：想一眼认出产物选「原始文件名」；要固定命名选「自定义」。
注意：自定义名批量处理会重名，系统会自动追加 (1)、(2)。

保留 Exif 标签 默认：关

是什么：拍摄时间、机型、GPS 定位等元数据。
为什么默认关：分享前抹掉隐私信息，是这类工具的核心用途之一。
什么时候改：要在相册里保留拍摄时间、做归档时打开。发到公开平台建议保持关闭。

图像 / 视频 / 音频 输出扩展名 默认：保持原格式

是什么：是否强制转换容器格式，例如一律转 .mp4、.jpg。
什么时候改：对方平台只认 mp4 → 选 .mp4；想更小 → 视频选 .webm，图片选 .webp。
注意：转 webm 时编码器会被 ffmpeg 自动定为 VP9，硬件加速档不适用。

将 GIF 视为视频 默认：关

是什么：把 GIF 当视频用 H.264 压，而不是按图片处理。
什么时候改：长动图想大幅瘦身时打开，通常能降到 1/5。
代价：输出会变成 mp4，丢失循环播放和透明通道。

压缩强度

视频 CRF 默认：23

是什么：恒定质量系数（0–51），控制「保画质还是保体积」。数值越小越清晰、文件越大。
经验值：18 视觉无损 · 20 高质量 · 23 日常 · 26 体积优先 · 28+ 明显变糊。
记住：CRF 每 +6，体积大约减半。
什么时候改：存档→18；发群怕大→26；只求能看清→28。

JPEG 图片质量 qscale 默认：10

是什么：图片压缩强度（1–31），数值越大越糊、越小。
建议：高质量 5–10；省空间 15–20；超过 25 肉眼可辨损伤。

FFmpeg 压缩预设 默认：medium

是什么：编码速度与效率的权衡：faster / fast / medium / slow / slower。
怎么选：手机端推荐 fast——同画质体积大约 +10%，速度提升 30% 左右；存档用 slow。
注意：硬件编码档不支持这个参数，会被忽略。

视频文件大小上限 默认：不限制

是什么：给一个目标体积（512K–100M），App 会反算码率，保证输出不超过它。
什么时候改：微信 25M、Discord 8M、论坛附件 2M —— 这个比 CRF 更好控结果。
注意：它和 CRF 同时设会互相打架，以上限为准；追求画质就别设上限。

分辨率与体积（收益最大）

最大视频分辨率 默认：1080

是什么：超过该值就等比缩小（只降不升）。
为什么重要：4K → 1080p 通常能省 70% 以上体积，还能让编码快好几倍。
怎么选：日常 1080 · 老机型/聊天 720 · 存档或大屏回放「不限制」。

最大图像分辨率 默认：2160

是什么：图片长边上限，4800 万像素照片会被压到 2160。
怎么选：聊天/发帖 2160 足够；要打印或二次修图选「不限制」。

编码器

视频编解码器 默认：不指定（软件 libx264）

选项用途
不指定固定走软件 libx264，画质/体积最均衡，兼容性最好
Copy只换容器不重编码，几秒完成，但体积不会变小
H.264 / H.265软件编码；H.265 同画质更小，但老设备可能播不动
H.264（硬件加速）走 h264_mediacodec，快 5–8 倍，码率固定、画质略弱
H.265（硬件加速）同上，体积更小，对播放端要求更高
VP9 / MPEG-4特殊兼容需求，一般用不到
什么时候用硬件：赶时间、批量、手机发热敏感；文字多的录屏、HDR 素材不建议。
兜底：硬件编码失败会自动改用软件编码重跑一次。

音频编解码器 默认：直接复制

是什么：Copy 不重新编码音频——最快且无损。
什么时候改：目标平台不认原音频格式（如 opus/flac）时改 AAC；想进一步缩体积也可以选 AAC。

自定义参数 默认：空

是什么：直接接管命令行，填了之后上面所有压缩参数都会被忽略。
示例：-c:v libx264 -crf 20 -vf scale=-2:720
注意：不懂 ffmpeg 语法就别填，容易压出无法播放的文件。

保存与缓存

压缩完成后自动保存 默认：开

是什么：压缩结果在弹出结果页之前先落盘一份。
存到哪：视频 Movies/FFShare、图片 Pictures/FFShare、音频 Music/FFShare。
为什么需要：压缩产物原本只在缓存里，1 小时后会被清理；不保存就等于白压。

保存位置 默认：系统相册

是什么：点一下选一个文件夹（走系统目录选择器），之后都存那里。
优点：不需要任何存储权限，且各 Android 版本行为一致。
恢复：「恢复为系统相册」清掉自定义目录。

立即清理缓存 按需

是什么：删除压缩过程中的临时文件，设置里会显示当前占用。
什么时候用：压过大文件后想立刻释放空间；平时超 1 小时会自动清。
放心：已保存到相册或已分享出去的成品不受影响。

其他

启用日志 默认：关

是什么：把每次执行的 ffmpeg 命令和完整输出存进「日志」页。
什么时候开：压缩报错要排查时；平时关掉可以少占空间。

常见问题

压完反而更大？

源文件本身已经是高压缩的结果（例如从别的 App 转存），再编码只会有损+膨胀。此时用 Copy 或直接用原文件更好。

报「压缩媒体时出错」？

先看弹窗里的 ffmpeg 末尾输出：出现 not divisible by 2 是分辨率问题；Unknown encoder 是编码器缺失；Permission denied 是文件读取权限。硬件档失败会自动回退一次软件编码。

硬件和软件怎么选？

同一段 86.9 MB / 1080p 视频实测：硬件 14.7 秒 / 26.5 MB，软件 108 秒 / 54.6 MB。快了 7 倍，但硬件是固定码率、画质略弱。

为什么结果页不自动弹分享了？

现在的流程是：压缩 → 自动保存 → 结果页。要发出去点「分享」即可，避免每次都中断你的操作。
